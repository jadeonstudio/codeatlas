# CodeAtlas — 실제 서비스 기획서

- 문서 버전: 1.0 / 2026-09-12
- 구현 릴리스: 0.1.0
- 소유 저장소: `jadeonstudio/codeatlas`
- 표시 언어: 한국어. 코드 심벌, API 경로, 고유 제품명은 원문 유지.
- 대상: 기존 개발 프로젝트를 가진 사용자와 그 사용자가 이미 사용하는 코딩 에이전트.

## 1. 제품 정의

**에이전트에게 소프트웨어를 이해·표현하는 공통 관점을 제공하고, 그 결과를 사용자가 탐색하면서 기존 에이전트와 개발을 이어가는 시각적 컨텍스트 계층.**

제품은 에이전트 지침, 공통 데이터 규격, 고정 시각화 화면과 얇은 선택 전달 기능을 제공한다. 분석·추론·소스 수정·실행·테스트·성능 측정은 사용자의 기존 에이전트가 담당한다. CodeAtlas가 새 에이전트를 실행하거나 기존 세션의 메시지를 가로채지 않는다.

분석 결과는 보고서로 끝나지 않는다. 사용자가 지도의 대상을 선택하고 기존 대화창에서 “여기는 어떻게 연결돼?”, “이렇게 변경하면 어디에 영향이 있어?”, “이 방식으로 수정해”라고 말하면 같은 에이전트가 선택을 읽고 대응한다. 수정 후에는 그 에이전트가 실제 프로젝트 상태를 다시 기록하여 지도가 갱신된다.

## 2. 확정된 사용자 요구사항

| R02 | 웹뿐 아니라 모바일·백엔드 등 범용 | 기술 스택 허용 목록 없이 의미 기반 노드·관계 사용 |

| R14 | 작업 범위를 임의로 축소하지 않음 | 웹·모바일·비화면 프로세스, 영향·성능·갱신 전체 루프 포함 |

## 3. 제공하지 않는 기능

CodeAtlas는 자체 AI 모델/API, 프레임워크별 소스 분석기, 런타임 트레이서, 테스트 실행기, 성능 예측 알고리즘, 자동 수정 엔진, 클라우드 오케스트레이터, 결제·회원가입 시스템을 만들지 않는다. 도구 자체가 사용자를 대신해 Git에 커밋하거나 DB를 변경하지 않는다.

표시 기능에 필요한 데이터 무결성 검사, 좌표 배치, 조회·검색, 스냅샷 비교, 세션 저장은 제공한다. 이는 제품을 이해하거나 영향도를 판단하는 분석 엔진이 아니다.

## 4. 지원 범위와 환경의 구분

제품의 표현 형식은 웹, iOS/Android, React Native, Flutter, 네이티브 앱, 서버, CLI, 게임, 데이터 파이프라인, 이벤트 기반 프로그램을 가정할 수 있다. 어떤 기술도 고정된 지원 스택 목록으로 차단하지 않는다.

그러나 에이전트가 소스에 접근하고 결과를 기록할 수 있어야 한다. 실행 검증에는 그 프로젝트의 빌드 환경·테스트 데이터·브라우저·에뮬레이터·외부 시스템이 필요하다. CodeAtlas 설치가 그러한 권한이나 도구를 추가하지 않는다. 에이전트 모델 브랜드와 그 모델을 실행하는 앱의 로컬 기능도 구분한다. 일반 클라우드 채팅에서 설치만으로 사용자의 localhost나 로컬 소스에 접근할 수 있다고 주장하지 않는다.

## 5. 전체 사용자 여정

### 5.1 설치

사용자가 저장소를 내려받고 대상 프로젝트에 `install`을 실행한다. 공통 런타임이 대상의 `.codeatlas/runtime`에 복사되어 원본 저장소를 이동해도 대상은 계속 사용할 수 있다. 선택한 에이전트의 스킬 폴더와 범용 지침을 설치한다. 기존 AGENTS.md/CLAUDE.md/.gitignore에는 식별 가능한 관리 블록만 추가하고 다른 규칙은 보존한다. 모델 설정·API 키·전역 권한은 변경하지 않는다.

설치 직후 그래프는 비어 있다. 실행되지 않은 분석을 완료했다고 표시하거나 데모 분석을 실제 프로젝트에 삽입하지 않는다.

### 5.2 최초 분석

사용자가 현재 에이전트에 CodeAtlas 지침을 읽고 분석하도록 지시한다. 에이전트는 세션 ID를 정하고 공통 viewer를 기존 터미널에서 실행한다. 인앱 브라우저가 있으면 그곳에 URL을 연다. 없으면 일반 로컬 브라우저를 쓰고 차이를 알린다.

분석은 제품 진입점, 사용자 동작, 기능, 조건, 계약, 서비스, 데이터와 외부 경계에 대한 실제 조사로 이루어진다. 에이전트가 읽은 코드나 실행 기록을 근거로 저장한다. 대규모 프로젝트는 도메인별로 조사하고 중간 결과를 게시할 수 있다. 기존 프로젝트를 완벽하게 이해했다는 무근거 선언 대신 확인/제외/미확인 범위를 기록한다.

### 5.3 탐색과 질문

처음에는 주요 흐름의 6–12개 항목을 보여준다. 선택하면 상세 패널에 설명, 플랫폼, 기능, 연결, 구현 위치와 근거가 나타난다. 연결선을 선택하면 해당 관계와 조건을 확인한다. 전체 검색은 현재 뷰에 없는 노드도 찾는다. 사용자에게 전체 API·함수 목록을 한 화면에 모두 노출하지 않는다.

단일 선택과 Shift 다중 선택을 지원한다. 선택은 현재 프로젝트 ID, 지도 revision, session, view, nodeIds, intent, 시각을 포함한다. 에이전트가 다음 대화 턴 시작 시 해당 세션의 선택을 읽는다. 화면 클릭만으로 질문이 전송되었다고 표시하지 않는다.

### 5.4 변경 영향 논의

사용자가 변경 의도를 기존 대화창에 입력한다. 에이전트는 현재 소스와 선택된 영역을 조사하여 영향 보고서를 게시한다. 관련성 자체와 오류 확정은 다르므로 직접 영향, 간접 영향, 영향 가능성을 별도로 표시한다. 각 항목에는 이유와 근거가 있고 필요한 경우 영향 전달 경로를 명시한다.

연결이 없거나 분석되지 않았다는 이유로 안전하다고 표시하지 않는다. 구현하지 않은 변경은 제안이다. 실제 테스트 실패를 재현했다면 해당 실행 근거와 조건을 기록한다.

### 5.5 성능 분석

에이전트가 성능 개선안을 조사하고 보고서를 게시한다. 숫자를 모르면 null 또는 미측정으로 표시한다. 추정 값은 추정 배지와 전제 조건을 갖는다. 실측 값은 측정 로그나 리포트 위치가 필수다. API 일부 처리시간 개선과 화면 전체 개선률을 구분한다. 캐시 도입으로 빨라져도 최신성이나 기능이 깨지면 성공으로 처리하지 않는다.

### 5.6 수정과 동기화

수정 허가는 기존 대화에서 받는다. 기존 에이전트가 소스와 테스트를 작업한다. CodeAtlas는 코드 수정 명령을 실행하지 않는다. 에이전트는 실제 변경 내용을 반영한 그래프와 검증 결과를 publish/patch한다. UI는 새 revision을 읽어 변한 항목을 표시하고 기존 탐색 위치를 가능한 한 유지한다.

사용자가 선택한 이후 지도 revision이 달라졌다면 선택은 오래된 상태로 표시된다. 에이전트는 이를 확인하고 대상을 다시 검토한 뒤 수정해야 한다. 이전 스냅샷과 비교할 수 있지만 지도 데이터 비교를 코드 의미 분석으로 오인하지 않는다.

## 6. 정보 모델

### 6.1 노드

`surface / feature / action / interface / service / data / state / process / external / resource / test / module`을 사용한다. 화면의 플랫폼, 프레임워크, 경로는 속성이다. 모바일의 푸시·권한·딥링크·오프라인 조건은 해당 의미 노드와 조건으로 표현한다. 백그라운드 프로세스를 화면 없는 프로젝트의 주 진입점으로 사용할 수 있다.

### 6.2 관계

`navigates / contains / triggers / calls / reads / writes / depends / invalidates / authorizes / publishes / consumes / tests / uses`를 지원한다. 관계의 의미를 정확히 구분하며 모든 것을 임의의 API 허브에 모으지 않는다. 방향과 조건을 명시한다. 에이전트가 연결을 추론했다면 inferred로 남긴다.

### 6.3 근거

source, runtime, test, measurement, inference, document를 분리한다. 소스에서 함수 호출을 발견한 것은 소스 근거이며 실제 실행 경로 관측과 같지 않다. observed에는 구체적 근거가 필요하고, inferred/unconfirmed는 불확실성을 숨기지 않는다. 테스트/측정 결과에도 해당 유형의 근거가 필요하다. 검증기 자체는 근거의 존재와 형식을 확인할 뿐 내용의 진실성을 판정하지 않는다.

### 6.4 보기와 보고서

보기는 하나의 그래프에서 필요한 nodeIds/edgeIds를 골라 구성한다. 선택적 좌표는 레이아웃 지시일 뿐 분석 결과가 아니다. 영향·성능·변경 보고서는 노드 참조, 기준 revision, 상태, 영향 사유, 테스트, 수치를 담는다.

스키마는 `schemas/graph.schema.json`, 실행 무결성 계약은 `src/contract.mjs`가 정의한다. 자세한 작성법은 AGENT_PROTOCOL.md를 따른다.

## 7. 화면 설계 원칙

승인 목업의 골격을 유지한다. 흰색과 옅은 회색 배경, 절제된 청색 포커스, 네이비 주 행동 버튼, 얇은 경계, 부드러운 카드 모서리와 점 패턴 캔버스를 사용한다. 웹과 모바일을 다른 메뉴 체계로 나누기보다 같은 그래프의 관점으로 탐색한다.

상단은 브랜드·검색·지도/영향/변경/설정만 제공한다. 좌측은 프로젝트와 정보 유형, 흐름, 저장한 보기로 제한한다. 중앙은 그래프와 작은 보기/줌 조작이다. 우측은 선택한 항목의 상세다. 초기부터 총합 통계 카드 다섯 개나 진행률 대시보드를 추가하지 않는다.

상세 패널의 기본은 설명과 주요 연결이다. 모든 코드를 기본 노출하지 않는다. 개요/연결/근거/변경 탭으로 깊이를 나눈다. 화면 캡처가 없으면 가짜 실제 캡처를 생성하지 않는다. 데모의 설명용 썸네일은 명확히 표시한다.

| 환경 표시 | 실제 확인한 기능과 호스트 미검증 항목을 구분 |

## 9. 예외와 복구

분석 전: 빈 상태와 기존 대화창에서 사용할 지시를 제공한다. 분석 중: 에이전트가 기록한 실제 요약과 이미 발견한 지도를 보여준다. 오류/중단: 마지막 게시된 지도를 보존한다. 서버 연결 끊김: 기존 화면을 남기고 상태를 표시하며 재연결을 시도한다. 서버 재시작으로 키가 변경되면 새 URL이 필요하다.

데이터가 잘못되면 게시를 거부하고 기존 그래프를 유지한다. 동시 작성 충돌 시 현재 revision을 다시 읽고 병합해야 한다. 앱 중단 후 잠금 디렉터리가 남으면 현재 작성 중인 프로세스가 없는지 확인한 뒤 잠금만 제거한다. 자동 강제 해제는 하지 않는다.

## 10. 설치·운영과 사용자 데이터

Node.js 22 이상과 로컬 브라우저만 런타임 전제다. 프로덕션 npm 의존성, API 키, 계정 가입이 없다. `.codeatlas`는 기본 Git 제외다. 공유가 필요한 지도는 명시적으로 export하여 민감정보 확인 후 전달한다. 런타임 삭제와 프로젝트 지식 삭제는 구분한다. uninstall은 소유 해시가 일치하는 파일만 제거하고 그래프·이력·캡처는 남긴다.

## 11. 검증 정책

개발 환경에서 실행한 자동 테스트와 호스트 앱 실사용 검증을 분리한다. CLI·HTTP·MCP 프로토콜·설치기를 로컬 자동 테스트로 검증한다. 공통 UI의 렌더링과 상호작용을 브라우저에서 확인한다. Codex/Claude/Grok 데스크톱 앱 각각의 설치·인앱 브라우저 실행은 해당 호스트가 있어야 확인할 수 있다. 실행하지 않은 호스트 검증을 완료로 표기하지 않는다.

제품의 장기 품질 기준은 에이전트가 이해한 범위의 정직성, 지도와 실제 코드의 불일치 최소화, 질문 대상 전달 오류 방지, 유용한 영향 설명과 검증 근거, 사용자 탐색 부담이다. 화려한 그래프의 노드 수나 근거 없는 완전성 백분율을 성공 지표로 삼지 않는다.

## 12. 향후 확장 경계

공통 표현 규격과 UI의 확장은 가능하다. 새 의미 유형이 필요하면 스키마 버전과 마이그레이션을 명시한다. 분석 자체를 제품 안으로 옮기는 것은 별도 사용자 결정 없이는 하지 않는다. 공개 마켓플레이스 등록, 원격 다중 사용자 호스팅, OAuth·권한 관리와 외부 tunnel은 현재 로컬 패키지의 설치 지원과 별개다. 임의로 로컬 프로젝트를 인터넷에 공개하지 않는다.
